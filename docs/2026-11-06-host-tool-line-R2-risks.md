# R2: risks of a host-tool line (rip-cage-mgp6)

Scope: a project-config-declared host-side tool exposing named verbs a caged agent may call, an optional approval hook, rc providing the channel both ways, nothing else reachable. Uses: non-HTTP keyholders (MTProto, WhatsApp, Signal, IMAP/SMTP, SSH, DB wires), request signing (SigV4, HMAC), reply-returns-a-key (token refresh).

Severity is relative to the rc threat model (CLAUDE.md philosophy; ADR-024): accidents and prompt-injection in scope, a motivated adversarial agent out of scope. "Already addressed by" cites existing rc text. External precedent is from general knowledge and not verified here.

Framing: the line is the first rc feature that deliberately gives the guest a way to cause host-privileged action. msb's boundary stops limiting whatever the line carries; the tool's verb set becomes the blast radius. ADR-024 D2 names two harm axes (exfiltration, on-device harm); a host-tool line adds a path that bypasses the egress allowlist, so the allowlist is no longer a sufficient exfil layer for any cage that has a line.

## External precedent (general knowledge, not verified in this session)

- ssh-agent forwarding hijack: a compromised remote uses loaded keys while the connection lives. Same shape as 4a/5e.
- Docker socket exposure: any caller of the endpoint is effectively host root; verbs and args are no access control unless the receiver enforces them.
- MCP tool poisoning and tool-output injection: tool descriptions and replies are untrusted model input (3c, 4c).
- Argument smuggling through "safe" wrappers around ssh/git/curl (ProxyCommand option, upload-pack option): 1b.

## Design constraints that fall out

1. **Exec argv only, never a shell.** Verbs declare a fixed argv template with typed slots (enum, regex, int, bounded string); `--` before positionals; leading-`-` values rejected unless declared. Done when no code path joins agent text into a command string.
2. **Closed schemas and hard caps.** Strict framing, unknown fields rejected, caps on request bytes, reply bytes, call duration, concurrency, calls per session.
3. **Parameters are constrained in the host-side declaration, not trusted from the agent.** Recipient/host/folder allowlists per verb. Verbs name capabilities, not protocols (4a, 4b).
4. **Fail-closed approval bound to the request.** Only an explicit ALLOW passes; crash, timeout, missing hook or empty output deny; approved bytes are hashed and the executed bytes must match; hook input on stdin. Approval is per-verb opt-in and may be an automatic policy script, so the default autonomous path never waits on a human.
5. **No credentials in replies by default.** Token-refresh verbs write to the host-side store msb substitutes from. A verb that returns a secret must declare it, and that cage is possession-mode for it (ADR-030, ADR-024 reflection residual).
6. **Normalised replies.** Fixed error vocabulary to the cage; raw stderr, paths and tracebacks stay in host logs. Reply content is untrusted input.
7. **Prefer a channel with no network socket.** The LAN-IP listener (spike Q3/Q4) is open to the LAN and source address is useless for identity. Otherwise: per-cage-per-line bearer secret on every request, one endpoint per pair, rotated on recreate, LAN exposure named in docs.
8. **Everything that defines authority is host-side outside every mount** (ADR-031 D5a): declaration, schemas, hook, and the resolved absolute paths of tool and hook. rc ignores workspace-local overrides.
9. **rc owns lifecycle.** Start/stop with the cage, record the pid, no orphan listeners; `rc doctor` lists lines beside `network.allow` and says plainly that a line bypasses egress policy. Done when destroying a cage leaves no listening process.
10. **Stay generic (ADR-005 D12).** rc supplies channel, caps, framing, the fail-closed hook contract and doctor visibility; the tool, verbs and hook are operator composition with recipes under `examples/`, never special-cased in rc.
11. **Name the severity class honestly.** A host-tool line is a path around the egress allowlist, and its blast radius is the verb set. Document it beside the DNS-exfil residual; under the stated model it is acceptable only if constraints 1, 3, 5 and 7 hold.
